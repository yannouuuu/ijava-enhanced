# Type booléen et expressions booléennes


::: question
**En ijava, comment s'écrit le type booléen ?**

- [ ] booléen
  > Incorrect : en (i)java tous les mots-clés du langage sont en anglais !
- [x] boolean
  > Tout à fait, bien joué.
- [ ] Boolean
  > Presque, mais seul le type String a la particulité de la majuscule, tous les autres types sont entièrement en minuscules.
- [ ] binary
  > Incorrect : même si il n'y a aussi que deux états pour ce type de donnée.
:::

::: question
**Le type booléen permet de représenter le résultat d'une ...**

- [ ] possibilité
  > Hum, pas du tout !
- [ ] alternative
  > Ah, ce n'est pas le même concept, l'alternative est la structure de contrôle if ...
- [x] condition
  > Bien joué, on utilise souvent ce terme qui est équivalent à "expression booléenne".
- [ ] vérification
  > Certes on vérifie l'état des variables, mais ce n'est pas ce terme qui est utilisé.
:::

::: question
**En ijava, quelles sont les deux seules valeurs d'un booléen ?**

- [ ] 0 / 1
  > Incorrect : d'autres langages permettrait cela, mais 0 ou 1 en Java, ce sont des entiers, donc de type int.
- [ ] TRUE / FALSE
  > Dommage, mais ce n'est pas le choix des créateurs/trices de Java ... même si cela aurait été un choix pertinent vu que ce sont des constantes !
- [ ] True / False
  > Incorrect : Java n'est pas python ;)
- [x] true / false
  > Effectivement, même si cela va à l'encontre de la convention de nommage des constantes en Java avec toutes les lettres en majuscules ...
:::

::: question
**L'opérateur ! correspond à ... ?**

- [x] la négation
  > Bravo, c'est tout à fait cela.
- [ ] l'inversion
  > Incorrect : même si conceptuellement on peut voir cela comme "inverser" la valeur, ce n'est pas le non de cet opérateur.
- [ ] la contradiction
  > Incorrect. Et l'on cherche à éviter les contradictions dans un système logique ;)
- [ ] la négativité
  > Pas loin ... mais c'est un trait de caractère à éviter :o)
:::

::: question
**En supposant que age vaut 18, à quelle valeur s'évalue l'expression : (age >= 18) en ijava ?**

- [ ] vrai
  > Non : certes cette condition est vérifiée, mais en ijava, pas de français !
- [ ] erreur à l'exécution
  > Incorrect : age est un entier, on compare donc deux entiers, il n'y a aucune erreur de syntaxe ou de sémantique.
- [x] true
  > Bravo, c'est effectivement cela.
- [ ] false
  > age = 18, donc (18 >= 18) est bien une condition vérifiée.
:::
